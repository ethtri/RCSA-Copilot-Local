## Comparison findings

1. **Application shell:** The white compact header, RCSA mark, three primary destinations, forest selected underline and quiet workspace control match the reference family. Assessment context and five steps remain compact. The former large introductory gap is removed.
2. **Canvas and panels:** Cool pale gray canvas, white work surfaces, thin neutral borders, restrained shadows and 6–8px corners match the extracted design system. There are no invented illustrations, decorative controls or extra visual themes.
3. **Type and readability:** The serif task title retains the reference character. Normal work and field content use the sans serif UI family. The complete captured rationales are readable without the original small nested scroll area. Operational table content is materially larger than the audited dashboard metadata.
4. **Assessment work:** The captured rating screen follows the reference's left risk rail, center owner fields and right pale-green AI area. The proposal was moved out of the central editor after the first browser comparison. The duplicate large analysis teaser was replaced by a simple full-analysis action. The owner's draft score remains visible; sources and the matrix open in a disclosure.
5. **Controls:** AI options and the owner conclusion are visible together. The existing, improve and new choices have distinct labels, a selected pale-green row, working review actions and a clear unimplemented-design boundary. The manual library action is secondary. Current/proposed counts are derived from records.
6. **Report:** The captured report uses a clear executive summary, a complete four-risk register and a visible Work records section. The primary risk's prior value is the actual Moderate 8. The new risk explicitly has no previous assessment. Table spacing, headings, borders and content hierarchy follow the report reference.
7. **Useful depth:** Source inspection, full analysis, history, control details and implementation plans remain available through working controls rather than appearing as permanent methodology paragraphs.

No clipped primary content, incorrect palette, unreadable form text or hidden central AI capability was found in these desktop captures. Responsive, keyboard, touch, reduced-motion and contrast results belong to the lead's separate acceptance checks; this visual comparison does not establish accessibility conformance.

## Intentional adaptations

- Actual synthetic records govern all source names, risk values, dates and status language. Generated reference copy is not treated as evidence.
- Before-controls and after-controls lenses remain separate. The reference's illustrative three-column data is represented by an explicit proposal preview and the owner editor, preserving field-level application and the last confirmed result without suggesting a false prior inherent assessment.
- The Controls risk selector sits above the related work areas. Existing Recommendations / Coverage & gaps / Implementation plan controls provide the functional navigation, avoiding a redundant second left navigation rail.
- The control conclusion uses a plain text editor. The reference's illustrated rich-text toolbar and attachment icons are omitted because those features are not part of the supported record contract.
- The plan is a working tab/editor rather than a decorative preview with invented task dates or fake file upload controls.
- The report capture shows a confirmed summary display state; Edit summary opens its editor. Its source/action drawer is closed in this capture. The reference depicts different editor/drawer states.
- The report retains the before-controls and confirmation columns because they describe the actual record. Report version controls make historical evidence and immutable editions inspectable.
- The source drawer and long editors preserve local draft values and have real close/return behavior. They are not permanently empty side panels added only to resemble the mockup.
