# Product refinement — November 14

The owner requested stronger visuals, visible AI, editable control relationships, intentional response creation, product language and a useful front-line dashboard. These requirements authorize the following changes to the earlier reference design.

## Design and implementation inventory

References: `concepts/feedback-refresh/dashboard.png`, `controls.png`, `response.png`, generated with the built-in image tool. Prompts are retained alongside them. Maintain the existing white/cool-grey/forest palette and Georgia/Segoe UI contrast. Add a deep-forest AI briefing, a full colored risk map, a native control/source network and a prior/current trajectory. No photographic assets are needed: these are native, interactive data visuals.

Dashboard: one assessment/process, three risk records; metrics, risk map, AI briefing, filterable attention queue and risk register. Counts derive from records. Reports remain an assessment drill-down. Product navigation reads Dashboard / Assessments / Reports. No invented notifications or account menus from the generated reference.

Controls: native risk/control/source relationships, mapped-control table, editable coverage rationale, library mapping, atomic replacement, removal of relationships and creation of proposed controls. Changes invalidate affected confirmations and response applicability. New controls receive no operating credit. Recompute applicability of the shared-source finding from current mappings.

Response: explicit Create risk response entry at residual assessment; strategy, rationale, owner, linked action/evidence or pending acceptance request. A source-backed AI draft requires a deliberate use action and human save. Current risk stays unchanged.

Generated mockups contain invented sample facts. Keep the documented stage order and existing shell; use the new concepts' data hierarchy rather than their inconsistent headers.
